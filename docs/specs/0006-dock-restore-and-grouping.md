# 0006 — Dock: restore minimised apps and group pinned Electron apps

Status: Implemented (branch improvements/shell-polish)

## Problem
1. Minimising Claude desktop and then clicking its dock icon does nothing. After the minimise, nothing outside
   WinGnome takes the foreground (or WinGnome's own window does), so `ExternalForeground.Handle` still points at
   the minimised window. `DockModelBuilder` then marks Claude as focused, `DockClickPlanner` plans
   *minimise*, and `SC_MINIMIZE` is posted to a window that is already minimised.
2. Pinned GitHub Desktop and VS Code show a second, unpinned icon when running. Their pins have a named
   AUMID (`com.squirrel.GitHubDesktop.GitHubDesktop`, `Microsoft.VisualStudioCode`), but Electron sets that ID
   process-wide, so their windows carry no AUMID that another process can read. The window falls back to a
   `path:` identity and neither the identity rule nor the exe-name rule (only used for `path:` pins) matches.
   GitHub Desktop also runs from a Squirrel `app-x.y.z` folder, not the stub its shortcut targets.

## Behaviour
- Clicking the icon of an app whose only or foreground window is minimised restores and focuses it, for every
  click action (*Focus or minimise*, *Cycle*, *Previews*).
- A minimised window is no longer shown as the focused app (focus highlight, intellihide).
- Running windows group into their pin when the pin's shortcut target is the window's executable, or when the
  window runs from a Squirrel `app-<version>` folder beside the shortcut's stub (`<root>\Name.exe` or
  `<root>\Update.exe`). This applies to named-AUMID pins too, except generated IDs
  (`Microsoft.AutoGenerated.{…}`), whose targets are generic launchers.
- For named-AUMID pins the path rule applies only to windows that report no AUMID of their own, so browser web
  apps (which run the browser's exe with their own AUMID) keep their own icon instead of joining a pinned browser.
  Path pins match by install whatever the window's AUMID (Squirrel apps such as Discord set one).
- No new settings.

## Non-goals
- Grouping apps whose window executable is unrelated to the shortcut target (launchers, browser PWAs).

## Design
- Core `RunningWindow.IsMinimized` (default false). `DockModelBuilder.IsFocused` requires the foreground window
  not to be minimised.
- Core `Windows/AppPathMatch`: `IsSameInstall(targetPath, processPath)` (canonical equality, or the Squirrel rule:
  process parent folder matches `app-\d+(\.\d+)*(-[\w.]+)?` and its parent equals the target's folder), and
  `IsGeneratedAumid(id)` (moved out of `AppCatalog`).
- `DockModelBuilder`: resolve every non-generated pin's target path with the existing `resolvePath`, and add a
  pass between the identity pass and the exe-name pass that matches `AppPathMatch.IsSameInstall`.
- App: `DockFeature.ToRunningWindow` passes `IsMinimized`; `ExternalForeground` clears `Handle` on
  `EVENT_SYSTEM_MINIMIZESTART` for that window; `AppCatalog.FindForWindow` uses the Squirrel rule so unpinned
  Squirrel apps get their catalogue name and icon.

## Safety and recovery
No system state changes.

## Footprint
None: one more WinEvent case in an existing subscription, and a path comparison per window per refresh.

## Acceptance criteria
1. Core tests: a minimised foreground window is not focused; clicking it plans *activate* in every click mode.
2. Core tests: `Microsoft.VisualStudioCode` pin with target `Code.exe` takes the `Code.exe` window; the GitHub
   Desktop stub pin takes the `app-3.6.6` window; a generated-AUMID pin targeting `cmd.exe` does not take
   `cmd.exe` windows; identity matches still win over path matches; no resolver behaves as before.
3. Manual: minimise Claude, click its dock icon, it comes back focused.
4. Manual: with GitHub Desktop pinned and open, the dock shows one icon with a running indicator.

## Risks and open questions
- Before the app catalogue loads, named-AUMID pins can't resolve their target and windows show unpinned until
  the catalogue's `Changed` refresh.
- Two pins with the same target group the window into the first one.
